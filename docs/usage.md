## 画面の構成

| 場所 | 内容 |
|---|---|
| 左端（アクティビティバー） | サイドバーに表示する内容を切り替えるアイコン。いちばん下の歯車は設定です |
| 左（サイドバー） | ファイル一覧など。⌘B で表示・非表示を切り替えます |
| 上（ツールバー） | 問題の選択欄と、「実行」「サンプルテスト」「ランダムテスト」「対話テスト」「デバッグ」「提出」のボタン。右端には、コンテストの開始までの時間・残り時間（[残り時間と通知](#残り時間と通知)） |
| 中央 | エディタ（タブで切り替え）。「過去問」のタブ（[過去問の一覧](#過去問の一覧)）もここに開きます |
| 右 | 問題文。右下は「提出結果」と「追跡」のタブ（[追跡するユーザー](#追跡するユーザー)） |
| 下 | 「実行ログ」「テスト結果」「エラー一覧」「デバッグコンソール」「履歴」のタブ |

アクティビティバーのアイコンは次の 4 つです。表示中のアイコンをもう一度押すと、サイドバーが閉じます。アイコンにマウスを乗せると、名前とキーが表示されます。

| アイコン | キー | 内容 |
|---|---|---|
| エクスプローラー | ⇧⌘E | [ファイル一覧](#ファイル一覧) |
| 検索 | ⇧⌘F | [検索](#検索) |
| 実行とデバッグ | ⇧⌘D | [デバッグ](#デバッグ) |
| コンテスト（旗のアイコン） | ⇧⌘C | [コンテストの提出状況](#コンテストの提出状況)（順位・予想 perf・予想 diff も）。[過去問の一覧](#過去問の一覧)もここから開きます |

- ツールバーのボタンにマウスを乗せると、キー（例：「実行（⌘R）」。設定で変えたものに合わせて変わります）と実行の対象が表示されます。
- 各ペインの境目はドラッグで調整できます。
- ウィンドウは 800 × 500 より小さくはなりません。

## 作業領域と信頼

問題を置くフォルダを「作業領域」と呼びます。「フォルダを開く」（⌘O）で選ぶと、次回の起動時にも同じフォルダとタブが開きます。

初めて開くフォルダでは「このフォルダを信頼しますか」と聞かれます。ビルドや言語サーバー（rust-analyzer・clangd・basedpyright）は、フォルダ内の設定（`build.rs` や `.cargo/config.toml` など）を通じてコードを実行することがあるためです。

| 選択 | できること | 次に開いたとき |
|---|---|---|
| 「信頼する」 | すべての操作 | 聞かれません |
| 「信頼しない」 | ファイルの編集、問題の表示、問題フォルダの作成（実行・テスト・デバッグ・言語サーバー・提出はできません） | 聞かれません |

「信頼しない」を選んだフォルダは、ファイル一覧の上の「信頼する…」から信頼し直せます（もう一度確認画面が出ます）。

## ファイル一覧

**作る**

- 見出しの「＋」で新しいファイルを、その隣のボタンで新しいフォルダを、選択中のフォルダに作ります。

**右クリックメニュー**（Esc で閉じます）

- ファイル：「名前の変更」「削除」
- フォルダ：「新しいファイル」「新しいフォルダ」「名前の変更」「削除」

**名前の変更と削除**

- 名前の変更では、大文字・小文字だけの変更もできます。
- フォルダの名前を変えると、その中のファイルのタブやブレークポイントも追従します。
- 削除したものはゴミ箱に移ります。フォルダを削除するときは、中のファイル数が確認画面に表示されます。
- シンボリックリンクはリンク自体を削除します（リンク先は残ります）。
- 実行・テスト・デバッグ・問題の作成をしている間は、フォルダの名前の変更や削除はできません。

**表示**

- Finder などで作業領域の中身を変えた場合は、IDE のウィンドウに戻ったときに一覧が更新されます。
- 左側の縦線でフォルダの階層が分かります。マウスを乗せると、その項目が属するフォルダの線が濃くなります。

## 検索

アクティビティバーの虫眼鏡（⇧⌘F）で、サイドバーが「検索」に切り替わります。エディタで 1 行の範囲を選んでいれば、その文字列を検索します。

- 入力が止まって少しすると検索が始まります（Enter ですぐに検索）。
- 右側のボタンで、大文字と小文字の区別（Aa）・単語単位（ab）・正規表現（.*）を切り替えます。正規表現の書き方は Rust の `regex` クレートに従います。
- 結果はファイルごとにまとめて表示されます。行を押すと、エディタでその場所に移動します。
- 検索の前に、未保存のタブは保存されます（検索は保存済みの内容を対象にするため）。

**検索の対象**

- 検索は 1 行単位です（複数行にまたがる一致は探しません）。
- `.git`・`target`・`node_modules` フォルダ、シンボリックリンク、1 MB を超えるファイル、テキストでないファイルは対象外です。
- 表示する一致は 2,000 件までです。

### 置換

検索欄の左の「▸」で置換欄を開き、「すべて置換」か、ファイルの行ごとの「置換」で置き換えます。置き換える前に確認ダイアログが出ます。

- 正規表現では `$1` や `${名前}` でキャプチャを参照できます。`$1_x` のように数字のあとに文字が続いても、`$1` は 1 番目のキャプチャです。`$` そのものは `$$` と書きます。
- 検索したあとで内容が変わったファイル（置換の直前に未保存の編集を保存したものも含む）は置き換えません。もう一度検索してから置換してください。
- 置換の直後なら「置換を元に戻す」で戻せます。
  - 戻せるのは直前の 1 回だけで、次の置換・フォルダの開き直し・アプリの終了までです。
  - 置換のあとで編集したファイルは戻しません。

## 問題とコンテスト

### コンテストを作る

1. ファイル一覧の見出しの「⤓」を押し、コンテスト ID（例：`abc480`）を入れて「作る」（または Enter）を押します。
2. 問題の一覧を読み込み、1 問ずつ問題を取得して、作業領域の直下にフォルダを作ります。進み具合（例：「3 / 7：abc480_c」）と、問題ごとの結果が表示されます。
3. 終わると、最初に作れた問題のファイル（Rust は `src/main.rs`、C++ は `main.cpp`、Python は `main.py`）が開きます。

言語（Rust・C++・Python）は、設定画面の「問題文」の「問題を作るときの言語」で決まります。

#### 作られるフォルダ

**Rust**

```
abc480/
  .cargo/config.toml    ← ビルド結果の置き場所（target）をコンテスト内で共有する設定
  abc480_a/
    Cargo.toml          ← パッケージ名は問題 ID（数字で始まる場合は p_ を付ける）、edition 2024、雛形の依存
    src/main.rs         ← 雛形
    examples/gen.rs     ← ランダムテストの生成器の雛形（問題文の入力の形式から作る）
    examples/naive.rs   ← ランダムテストの愚直解の雛形（src/main.rs と同じ中身）
    test/sample-1.in    ← サンプル
    test/sample-1.out
    …
    test/input.txt      ← 「実行」で使う標準入力（入力例 1）
    test/compare.json   ← 比較方法と制限（時間制限は問題の制限＋500 ms、メモリは問題の制限。誤差の指定があれば float）
  abc480_b/
  …
```

**C++**（`.cargo/config.toml` の代わりに `.clang-format` を置きます）

```
abc480/
  .clang-format         ← 整形スタイル（LLVM スタイル、インデント 4）。自由に書き換えて構いません
  abc480_a/
    main.cpp            ← 雛形
    compile_flags.txt   ← ほかのエディタの clangd 用のオプション（IDE の clangd は、IDE が渡すオプションを使います）
    examples/gen.cpp    ← 生成器の雛形（Rust と同じ）
    examples/naive.cpp  ← 愚直解の雛形（main.cpp と同じ中身）
    test/…              ← Rust と同じ
```

**Python**

コンテストのフォルダには何も置かず、問題ごとに `main.py`（雛形）・`examples/gen.py`・`examples/naive.py`（Rust と同じ）・`test/…`（Rust と同じ）だけを作ります。

生成器と愚直解の雛形については、[ランダムテスト](#ランダムテスト)を見てください。

#### 作るときの決まり

- **中断**：作成中は「止める」で中断できます（取得中の問題を終えたところで止まります）。作り終えた問題はそのまま残ります。
- **上書きしない**：すでにあるファイルは上書きせず、結果に「すでにありました」と表示します。
  - 別の言語の問題フォルダ（例：Rust の `abc480_a/` があるところに C++ で作る）には、ファイルを追加せずにお知らせします。
  - サンプルを削除した場合は、もう一度作ると削除したものだけを書き直します。
  - 中身を変えたサンプルは書き換えません（「中身が違うので書いていません」と表示）。
- **通信**：AtCoder にアクセスするのは「作る」を押したときだけで、1 問ごとに 1 秒の間隔をあけます。一度取得した問題はアプリのフォルダに保存し、次からは再取得しません。
- **開始前・開催中**：開始前のコンテストは問題の一覧が読めないので作れません。開催中のコンテストは、ログインしていれば作れます（ログインは [提出](#提出) を参照）。

### 1 問だけ作る

1. 上の選択欄にコンテスト ID を入れて「一覧」を押し、問題を選びます。右に問題文が表示されます。
2. 問題文の欄の「…」→「この問題を作る」を押すと、その問題のフォルダだけを作ります。

- 言語は、設定画面の「問題文」の「問題を作るときの言語」で決まります。
- 開いているファイルのフォルダ名からすでに問題が決まっている場合（例：`abc480_a/` 内のファイル）は、このボタンは表示されません。

### 雛形

アプリのフォルダ（[データの場所](#データの場所)）の `templates/` に次のファイルを置くと、問題を作るときにその内容が使われます。置いていないものは、IDE 内蔵の最小限の雛形になります。

フォルダは、設定画面（⌘,）の「テンプレート」にある「テンプレートのフォルダを開く」から開けます。

| ファイル | 使われる場所 | 置いていないとき |
|---|---|---|
| `templates/main.rs` | `src/main.rs` の内容 | `fn main() {}` |
| `templates/dependencies.toml` | `Cargo.toml` の `[dependencies]` の内容 | `proconio = { version = "=0.5.0", features = ["derive"] }` |
| `templates/main.cpp` | C++ の `main.cpp` の内容 | `#include <bits/stdc++.h>`、`using namespace std;`、入出力を高速化する 2 行だけの `main()` |
| `templates/main.py` | Python の `main.py` の内容 | 空の `def main():` と、それを呼ぶ `main()` |

`dependencies.toml` の例（バージョンはジャッジに合わせます）：

```toml
proconio = { version = "=0.5.0", features = ["derive"] }
ac-library-rs = "=0.2.0"
superslice = "=1.0.0"
itertools = "=0.14.0"
```

- `proconio` の `#[fastout]` を使うには `features = ["derive"]` が必要です（ジャッジも derive を有効にしています）。
- 雛形を変えても、すでに作った問題の `Cargo.toml`・`src/main.rs`・`main.cpp`・`main.py` は変わりません。

### 問題文の表示

問題文（日本語）・制限・数式が表示されます。

読み込めないとき（ネットワークにつながっていない、ページの構造が変わったなど）は、理由と「公式ページを開く」「もう一度試す」が表示されます。

#### 難易度（diff）

終わったコンテストの問題では、制限の後ろに AtCoder Problems の難易度（「diff 581」。50% の確率で解けるレート）を、AtCoder のレートの色で表示します（[過去問の一覧](#過去問の一覧)と同じデータ）。

- 元にした結果が少ない試験的な推定には「?」が付きます。
- AHC など、AtCoder Problems に難易度がない問題には出ません。

#### 見出しのボタン

見出しの右には「input! を作る」「サンプルを保存」と「…」が並びます。「…」からは、次のものを選べます。

| 「…」の項目 | すること |
|---|---|
| 「再取得」 | 問題を読み込み直します |
| 「公式ページ」 | ブラウザで開きます |
| 「解説」 | その問題の解説の一覧をブラウザで開きます |
| 「この問題を作る」 | [1 問だけ作る](#1-問だけ作る) |
| 「生成器と愚直解を作る」 | [ランダムテスト](#ランダムテスト) |
| 「白紙から解き直す」 | [解き直し](#解き直し) |

見出しに並べるボタンは、設定画面の「問題文」で選べます。

#### 「自力」「解説」「解き直す」

制限の行の下（右寄せ）に並びます。

- 「自力」「解説」：その問題をどう解いたかを記録します（[自力 AC・解説 AC の記録](#自力-ac解説-ac-の記録)）。
- 「解き直す」：解き直す問題に印を付けます（[解き直し](#解き直し)）。

#### 画像

問題文の画像（AtCoder の画像のサーバー `img.atcoder.jp` のもの）も表示します。

- 問題を表示すると、文が先に出て、画像はあとから読み込まれます（読み込み中は「［画像を読み込んでいます…］」）。
- 読み込んだ画像はアプリのフォルダの `problems/<コンテスト>/images/` に保存するので、次からは通信せずに表示します。
- 画像は欄の幅に収まるように縮め、背景が透明な図も読めるように後ろを白くします（設定の「色」の「画像の背景」で変えられます）。
- 読み込むのは、問題を表示したときだけです（「コンテストを作る」「この問題を作る」では読み込みません）。画像は 1 秒ずつ間隔をあけて読み、ログインのセッションは送りません。
- 表示するのは PNG・JPEG・GIF・WebP の画像だけで、1 枚 5 MB・1 問 20 枚までです。ほかの場所の画像や、それを超えるものは「［画像があります。公式ページで見てください］」と表示します。
- 読み込めなかった画像は「［画像を読み込めませんでした。公式ページで見てください］」と表示し、次に問題を表示したときに読み込み直します。

### input! を作る

問題文の欄の「input! を作る」を押すと、問題文の「入力」の形式と「制約」から、入力を読むコードを作ります（保存済みの問題文を使うので、再取得はしません）。Rust では proconio の `input!` の中身、C++ と Python では「入力のコードを作る」というボタンになり、それぞれの書き方のコードを作ります。

> 作られた型や形は、必ず問題文と見比べてください。入力例と合っていても、型が正しいとは限りません。

#### Rust の場合

**作られるコード**

- 整数の型は、制約で負の値がありうるなら `i64`、0 以上なら `usize` にします。制約から判断できないときは `i64` にして注意を出します。
- 文字列は `Chars`、1 文字は `char`、実数は `f64` です。
- 変数名は、問題文の変数名を小文字にしたものです（縦に並ぶ組は名前をつなげます。`X_i Y_i` なら `xy`）。Rust の予約語と重なる場合は末尾に `_` を付けて（`fn_`・`if_` など）注意を出します。
- 作った形で入力例を読み込めるかを確かめます。合わないときは「入力例 N と合いません（…）」と表示されます。
- テストケースが複数ある問題では、`main()` 用（`t: usize`）と `solve()` 用（1 ケース分）に分けて作ります。
- クエリ（`query_1 … query_Q`）や読み取れない形式があると、その手前までを作り、残りはコメントと注意でお知らせします。

**ボタン**

- **「solve() の input! を置き換える」**：エディタで開いている `.rs` ファイルの `fn solve` の中にある最初の `input! { … }` の中身を置き換えます（なければ `fn solve` の先頭に入れます）。⌘Z で元に戻せます。
  - テストケースが複数ある場合は、`main()` の `input!` も `t: usize` にします。`main()` に `input!` がなければ何もしないので、`for _ in 0..t { solve(); }` は自分で書いてください。
  - 設定画面の「問題文」で「テストケースが複数のとき、main() に for も書く」をオンにすると、`main()` に `input!` がなくても先頭に入れ、`main()` 内の `solve();` を `for _ in 0..t { solve(); }` に書き換えます（すでに `for` などの中で呼んでいれば、そのままにします）。
- **「コピー」**：作ったコードをクリップボードにコピーします。`fn solve` がないファイルではこちらを使ってください。

**問題を作るときに入れておく**

設定画面の「問題文」で「問題を作るときに input! を入れておく」をオンにすると、「コンテストを作る」「この問題を作る」のときに、テンプレートの `fn solve` の `input!` を自動で作ったものにしておきます（テストケースが複数ある場合は「main() に for も書く」の設定に従います）。

- 作成結果には、問題ごとに「input! を入れました」（一部だけ作れたときや入力例と合わないときは、その旨も）か「input! を作れませんでした（理由）」が表示されます。
- 作れなかった問題や、すでにある `main.rs` はそのままです。

#### C++ の場合

選んでいる問題の `<コンテスト>/<問題>/` が C++ のフォルダなら（フォルダがなければ、設定の「問題を作るときの言語」が C++ なら）、ボタンが「入力のコードを作る」になり、変数の宣言と `cin >>` の行を作ります。

```cpp
long long N;
cin >> N;
vector<long long> A(N);
for (auto& a : A) cin >> a;
vector<long long> X(N), Y(N);
for (int i = 0; i < N; i++) cin >> X[i] >> Y[i];
```

- 整数はすべて `long long`、実数は `double`、1 文字は `char`、文字列は `string` です。
- 変数名は問題文のまま（`N`・`A`）で、縦に並ぶ組は列ごとの `vector` にします。C++ の予約語と重なる名前には末尾に `_` を付けます。
- 「solve() の入力を置き換える」は、開いている C++ ファイルの `solve()`（なければ `main()`）に、`// 入力（AtCoder Studio）` と `// 入力ここまで` のコメントで囲んでコードを書き込みます。⌘Z で元に戻せます。
  - この目印があれば、その間を置き換えます。
  - なければ、関数の先頭（`main()` の場合は `ios::sync_with_stdio(false);`・`cin.tie(nullptr);` の後ろ）に入れます。
- テストケースが複数ある問題では `solve()` が必要です。`main()` に `T` を読むコードを入れ、「main() に for も書く」がオンなら、`main()` の `solve();` を `for (int i = 0; i < T; i++) solve();` に書き換えます。
- 「問題を作るときに input! を入れておく」がオンなら、`main.cpp` にも同じように入れます。

#### Python の場合

選んでいる問題のフォルダが Python なら（フォルダがなければ、設定の「問題を作るときの言語」が Python なら）、ボタンが「入力のコードを作る」になり、1 行ずつ `input()` で読むコードを作ります。

```python
N, M = map(int, input().split())
A = list(map(int, input().split()))
X = [0] * M
Y = [0] * M
for i in range(M):
    X[i], Y[i] = map(int, input().split())
S = [input() for _ in range(N)]
```

- 整数は `int`、実数は `float`、文字列と 1 文字は `str` のままです。
- 区切りのないグリッドは行ごとの文字列のリスト（`C[i][j]` で 1 文字）、空白区切りのグリッドはリストのリストになります。
- 変数名は問題文のままで、縦に並ぶ組は列ごとのリストにします。Python の予約語や、生成コードで使う名前（`input`・`int`・`map`・`list`・`range` など）と重なる名前には、末尾に `_` を付けます。
- 入力例との照合では、行の分かれ方（1 行あたりの値の数、横に並ぶ値の長さ、縦に並ぶ行数）も確認します。合わないときは「入力例 1 と合いません（2 行目：…）」のように表示されます。
- 「solve() の入力を置き換える」は、開いている `.py` の `def solve():`（なければ `def main():`）に、`# 入力（AtCoder Studio）` と `# 入力ここまで` のコメントで囲んでコードを書き込みます。⌘Z で元に戻せます。
  - 目印があれば、その間を置き換えます。
  - なければ、関数の先頭に入れます（中身が `pass` だけなら、`pass` と置き換えます）。
- テストケースが複数ある問題では `def solve():` が必要です。`main()` に `T = int(input())` を入れ、「main() に for も書く」がオンなら、`main()` の直下にある `solve()` を `for _ in range(T):` の中に入れます。
- 「問題を作るときに input! を入れておく」がオンなら、`main.py` にも同じように入れます。

## 実行とテスト

### 実行の対象

開いているファイルから、何を実行するかを決めます。決められないファイルを開いているときは、直前の対象をそのまま使います。

| 言語 | 対象になるとき |
|---|---|
| Rust | 開いている `.rs` ファイルから、どのパッケージのどのバイナリを実行するかを決めます |
| C++ | `Cargo.toml` のないフォルダの `main.cpp`、またはそのフォルダの `test/` 内のファイルを開くと、そのフォルダが対象になります（[C++](#c)）。同じフォルダに `Cargo.toml` もあれば Rust として扱います |
| Python | `Cargo.toml` も `main.cpp` もないフォルダの `main.py`、またはそのフォルダの `test/` 内のファイルを開くと、そのフォルダが対象になります（[Python](#python)） |

対象のフォルダ名が問題 ID の形（例：`abc480_a`）になっていれば、問題も自動で決まります。

### テストケースのフォルダ

| 場所 | 使われるとき |
|---|---|
| `test/<バイナリ名>/` | あれば常に |
| `test/` | パッケージのバイナリが 1 つのとき（「コンテストを作る」で作ったものはこちら） |

フォルダに置くファイル：

| ファイル | 用途 |
|---|---|
| `sample-N.in`・`sample-N.out` | サンプルテストの入力と期待出力（N は 1 から）。`.out` がなければ、比べずに出力を見るだけのケース（目視確認）になります |
| `input.txt` | 「実行」で使う標準入力。なければ空の標準入力で実行します |
| `compare.json` | 比較方法と制限（[下記](#comparejson)） |
| `random-N.in`・`random-N.out` | ランダムテストで失敗したケース（IDE が保存します） |
| `interactive-N.in` | 対話テストでジャッジに渡すケース |

### 実行・サンプルテスト

- **「実行」（⌘R）**：`cargo build --release` でビルドし、`input.txt` を標準入力にして実行します。出力は「実行ログ」に表示されます。
- **「サンプルテスト」（⇧⌘R）**：`sample-N`（と `random-N`）をすべて実行し、「テスト結果」に判定・実行時間・メモリを表示します。入力・期待する出力・実際の出力を並べて見比べられます。
  - 「このケースだけ実行」「失敗したケースだけ再実行」「このケースをデバッグ」「出力を期待出力として保存」のボタンもあります。
- 実行中は、ボタンが「停止」（⌘.）に変わります。
- ビルドに失敗すると「エラー一覧」に表示されます。行を押すと、エラーの場所に移動します。
- 判定は手元でのものなので、ジャッジと同じ結果になるとは限りません。実行ログには、手元とジャッジの Rust のバージョンが表示されます。

#### テストケースを足す

「テスト結果」のタブの上にあります（テストをまだ実行していなくても使えます）。

「入力」と「期待出力」を貼り付けて「足す」を押すと、実行の対象のテストケースのフォルダに、今ある `sample-N` のいちばん大きい番号の次（例：`sample-4.in`・`sample-4.out`）として足します。

- 改行は LF にそろえ、最後に改行がなければ足します。
- 期待出力を空にすると `.in` だけを作ります（目視確認のケース）。
- すでにあるファイルは上書きしません。1 つの欄は 4 MB までです。
- 足しただけでは実行しないので、続けて「サンプルテスト」を押してください。
- 足したケースを直す・消すときは、ファイル一覧とエディタを使います。
- 信頼していないフォルダでは使えません。
- あとで「サンプルを保存」を押しても、足したケースは消えません（「問題のサンプルより大きい番号の … があります」と知らせます）。

### C++

`main.cpp` のあるフォルダ（例：`abc480/abc480_a/main.cpp`）を、C++ の 1 問として扱います。テストケースのフォルダ（`test/`）は Rust と同じです。

#### コンパイラ

Homebrew の GCC（`brew install gcc` で入る `g++-15`）が必要です。Apple の clang（Xcode Command Line Tools の `clang++`）は `#include <bits/stdc++.h>` が使えないため使いません。

g++ は、次の順に探します。

1. `settings.json` の `cpp.compiler`（g++ の絶対パス）
2. `/opt/homebrew/bin/g++-15`
3. `PATH` 上の `g++-15`
4. `/usr/local/bin/g++-15`

#### ビルドと実行

- **「実行」「サンプルテスト」**：`g++-15 -std=gnu++23 -O2 -Wall -Wextra -DATCODER -DONLINE_JUDGE …` でビルドし、フォルダ内の `target/main` を実行します。
- オプションはジャッジの「C++23 (GCC 15.2.0)」に合わせていますが、`-march=native`・`-fopenmp` などのオプションや、Boost などのライブラリは付けません（実行ログにも表示されます）。
- コンパイルエラーや警告は「エラー一覧」に表示され、押すとその行に移動します。
- `.cpp`・`.cc`・`.cxx`・`.hpp`・`.hh`・`.h` のファイルは C++ として色分けされます。

#### AC Library

アプリのフォルダの `libraries/ac-library/atcoder/` にあれば、ビルド時に読み込みます（`#include <atcoder/all>` など）。

- ジャッジと同じ 1.6 を [GitHub の atcoder/ac-library](https://github.com/atcoder/ac-library)（ライセンスは CC0）からダウンロードし、`atcoder/` フォルダをそこに置いてください。
- 実行ログの最初に、読み込む場所（なければ「なし」）が表示されます。

#### 自作のライブラリ（C++）

アプリのフォルダの `libraries/cpp/` にヘッダーを置くと、`#include "segtree.hpp"`・`#include "graph/dijkstra.hpp"` のように読めます（ビルドと clangd が、このフォルダも探します）。

- 設定画面の「テンプレート」の「ライブラリのフォルダを開く」で開けます（なければ作ります）。
- フォルダを作った直後は、メニューの「言語サーバーを再起動」を行うと clangd が読み込みます。
- 実行ログの最初に、読み込む場所が表示されます。

**提出と「コードをコピー」のときに展開します**

`main.cpp` の、行の頭が `#include "…"` の行を、そのヘッダーの中身に置き換えて 1 つのファイルにします。

- 探す順は g++ と同じく、読む側のファイルのフォルダ（`main.cpp` の隣）→ `libraries/cpp/` です。
- ヘッダーの中の `#include "…"` も展開し、同じヘッダーは 1 回だけ入れます（`#pragma once` の行は消します）。
- 展開した中身の前後には `// ---- 展開：segtree.hpp ----`・`// ---- ここまで：segtree.hpp ----` のコメントが入ります。
- `#include <…>` と、AC Library にあるもの（`#include "atcoder/dsu"` など）は展開しません（ジャッジにあります）。
- 見つからないヘッダーは展開せず、提出前のチェックで注意を出します。
- 行ごとに見るだけなので、`/* … */` の中や `#if` の中の `#include "…"` も展開します。

**送る前の確認**

- 提出のときは、ヘッダーを展開したら、送る前に展開したものを手元の g++ で文法だけ確認します（`libraries/cpp/` は読まずに確認するので、展開したものだけでコンパイルできるかが分かります）。
- エラーがあれば送らず、g++ のエラーを表示します（`<stdin>` の行番号は展開したあとのものです）。
- 展開したあとが 512 KiB を超えるときも送りません。

#### C++ で使えるほかの機能

| 機能 | 内容 |
|---|---|
| 問題・コンテストを作る | C++ を選べます（[コンテストを作る](#コンテストを作る)） |
| 提出 | 言語は「C++23 (GCC 15.2.0)」です（[提出](#提出)） |
| 補完などの言語機能 | clangd が担当します（[エディタと言語サーバー](#エディタと言語サーバー)） |
| デバッグ | [C++ のデバッグ](#c-のデバッグ) |
| ランダムテスト・対話テスト | 生成器・愚直解・ジャッジは `examples/gen.cpp`・`examples/naive.cpp`・`examples/judge.cpp`（`main_gen.cpp` などの名前でも可）です（[ランダムテスト](#ランダムテスト)・[対話テスト](#対話テスト)） |
| 入力のコード | 問題文から、宣言と `cin >>` を作れます（[input! を作る](#input-を作る)） |

### Python

`main.py` のあるフォルダ（例：`abc480/abc480_a/main.py`）を、Python の 1 問として扱います。テストケースのフォルダ（`test/`）は Rust と同じです。同じフォルダに `Cargo.toml` や `main.cpp` もある場合は、そちらの言語として扱います。

#### 処理系

ジャッジの「Python (CPython 3.13.7)」か「Python (PyPy 3.11-v7.3.20)」に合わせます。設定画面（⌘,）の「Python」の「処理系」か、`settings.json` の `python.interpreter`（`cpython`〔既定〕または `pypy`）で選びます。

- **必要なもの**：CPython なら `python3.13`（`brew install python@3.13`）、PyPy なら `pypy3.11` か `pypy3`（`brew install pypy3.11`）。IDE がインストールすることはありません。
- **探す順**：`settings.json` の `python.cpython`・`python.pypy`（処理系の絶対パス）→ `/opt/homebrew/bin` → `PATH` → `/usr/local/bin`
- **バージョン**：ジャッジと同じバージョン（CPython は 3.13、PyPy は Python 3.11 対応のもの）でなければ、インストール方法を表示して実行しません。3.13.7 と 3.13.15 のような細かいバージョンの違いは、実行ログに表示したうえで実行します。

#### 実行

- **「実行」「サンプルテスト」**：`python3.13 -B -X int_max_str_digits=0 main.py` のように実行します。ビルドはありません。
  - `-X int_max_str_digits=0` はジャッジと同じ指定です。
  - `-B` で `__pycache__` を作らないようにしています。
- 実行の前に構文をチェックします。構文エラーがあると CE になり、「エラー一覧」からその行に移動できます。
- **環境変数**：ターミナルなどで設定した `PYTHONPATH`・`PYTHONSTARTUP` などの `PYTHON…` の変数は IDE が外し、代わりに `PYTHONPATH` に自作のモジュールのフォルダ（`libraries/python/`）を渡します。ランダムテスト・対話テスト・デバッグも同じです。
- モジュールは `main.py` のフォルダ → `libraries/python/` → 標準ライブラリの順に探されます。
- `.py` ファイルは Python として色分けされます。

#### 自作のモジュール

アプリのフォルダの `libraries/python/` に、モジュール（`mylib.py`）かパッケージ（`mylib/__init__.py` と中のモジュール）を置くと、`main.py` で `from mylib import f` のように使えます。

- 設定画面の「テンプレート」の「ライブラリのフォルダを開く（Python）」で開けます（フォルダがなければ作ります）。
- `main.py` の隣のモジュールも使えます。
- 補完・定義ジャンプも効きます。
- 提出と「コードをコピー」のときは `main.py` に埋め込みます（[Python の自作のモジュールの埋め込み](#python-の自作のモジュールの埋め込み)）。

#### Python で使えるほかの機能

| 機能 | 内容 |
|---|---|
| 問題・コンテストを作る | 設定画面の「問題文」で「問題を作るときの言語」を Python にします（[コンテストを作る](#コンテストを作る)） |
| 提出 | 言語は、設定の処理系に応じて「Python (CPython 3.13.7)」か「Python (PyPy 3.11-v7.3.20)」になります（[提出](#提出)） |
| 補完などの言語機能 | basedpyright が担当します（[エディタと言語サーバー](#エディタと言語サーバー)） |
| デバッグ | debugpy を使います（[Python のデバッグ](#python-のデバッグ)） |
| ランダムテスト・対話テスト | 生成器・愚直解・ジャッジは `examples/gen.py`・`examples/naive.py`・`examples/judge.py`（`main_gen.py` などの名前でも可）です |
| 入力のコード | 問題文から作れます（[input! を作る](#input-を作る)） |
| スニペット | [スニペット](#スニペット) |

### compare.json

テストケースのフォルダに置く、比較方法と制限の設定です。書かなかった項目は既定値になります。

```json
{ "mode": "float", "abs": 1e-6, "rel": 1e-6, "timeLimitMs": 2500, "memoryLimitMiB": 1024, "randomCount": 100 }
```

| 項目 | 意味 | 既定値 |
|---|---|---|
| `mode` | `whitespace`（空白・改行の違いを無視）、`exact`（完全一致）、`float`（`abs`・`rel` の誤差の範囲なら正解）、`none`（比較しない） | `whitespace` |
| `abs`・`rel` | `float` のときの絶対誤差・相対誤差（少なくとも一方を指定） | なし |
| `timeLimitMs` | サンプルテスト・ランダムテスト・対話テストの時間制限（60000 まで。対話テストではやり取り全体にかかる） | 2500 |
| `memoryLimitMiB` | メモリ制限（65536 まで）。実行中も監視していて、超えた時点で止めて MLE にします | 1024 |
| `randomCount` | ランダムテストの回数（1〜10000） | 100 |

#### 問題を作ったときの中身

「コンテストを作る」「この問題を作る」で作ったフォルダには、問題に合わせた内容が最初から入っています。読み取りが間違っていたら、手で直してください。

- 時間制限は問題の制限＋500 ms、メモリは問題の値です。
- 問題文に「どれを出力しても正解」のように答えが複数ありうる書き方があれば、`none`（目視で確認）になります。
- そうでなく「出力」に「誤差が 10^{-k} 以下」とあれば、`float` と `1e-k` になります。

#### 答えが複数ありうる問題

答えが複数ありうる問題で `whitespace` のままだと、正しい別解も AC にならず、提出前のサンプルテストで止まってしまいます。

- その場合は `"mode": "none"` にしてください（目視確認のケースがあると、提出前のテストでは止めずに確認ダイアログを出します）。
- 設定画面の「提出」で、提出前のサンプルテスト自体をオフにすることもできます。

### ランダムテスト

解答と愚直解（遅くて確かな解き方）に同じ入力を与えて、出力を比べます。入力は生成器が作ります。

#### 生成器と愚直解を置く場所

| 言語 | 生成器 | 愚直解 |
|---|---|---|
| Rust | `examples/<バイナリ名>_gen.rs`（バイナリが 1 つなら `examples/gen.rs` でも可） | `examples/<バイナリ名>_naive.rs`（バイナリが 1 つなら `examples/naive.rs` でも可） |
| C++ | `examples/gen.cpp`（`examples/main_gen.cpp` でも可） | `examples/naive.cpp`（`examples/main_naive.cpp` でも可） |
| Python | `examples/gen.py`（`main_gen.py` でも可） | `examples/naive.py`（`main_naive.py` でも可） |

- Rust は、同じパッケージの `examples/` に置きます。
- C++ は、提出用と同じオプションでビルドします（ビルド結果はフォルダ内の `target/examples/` に置きます）。
- 生成器には、毎回違う seed（整数）が第 1 引数として渡されます。その seed をもとに入力を作り、標準出力に出力してください。

#### ランダムテストの実行

「ランダムテスト」を押すと、最大 `randomCount` 回、解答と愚直解の出力を比べます。最初に一致しなかった回で止まり、そのケースを `random-N.in`・`random-N.out` として保存します（次回からはサンプルテストでも実行されます）。

#### 生成器と愚直解の雛形

「コンテストを作る」「この問題を作る」では、`examples/gen.*`（生成器）と `examples/naive.*`（愚直解）を最初から置きます（すでにあれば上書きしません）。

前に作ったフォルダには、問題文の欄の「…」→「生成器と愚直解を作る」で、ないものだけを置けます（そのフォルダのファイルを開いているときに押せます）。

**愚直解の雛形**

`main` と同じ中身（テンプレートと、設定に従って入力のコード）です。solve に全探索などの遅くて確かな解き方を書いてください。

**生成器の雛形**

問題文の「入力」の形式どおりに、seed から小さな入力を作ります。値の範囲はファイルの頭の定数（`N_MIN`・`N_MAX` など）で、問題に合わせて直せます。

| 値 | 範囲 |
|---|---|
| 長さ・個数・テストケースの数に使う値（`N` など） | 制約の下限〜下限+7（下限が読めなければ 1〜8） |
| ほかの整数 | 下限〜下限+9（下限が負なら −10〜10）。上限の数がそれより小さければその数まで、上限が先に出てくる値（`1 ≤ X_i ≤ N` の `N`）ならその値まで |
| 実数 | 下限〜下限+10 の小数 2 桁 |
| 文字 | 制約に選択肢（「`.` または `#`」「L, R のいずれか」）があればその中から、なければ英小文字 `a`〜`c` |
| 文字列 | 長さは 1〜8 |

生成器の雛形が満たさないもの：

- 「相異なる」「順列」「木」「連結」などの制約や、`A_i < B_i` のような値どうしの関係は満たしません。そうした制約の行は、生成器の頭のコメント（「満たしていない制約」）や定数の横のコメントに書くので、必要なら直してください。
- クエリや読めない形式は、そこまで作って「書き足してください」とコメントを残します。

### 対話テスト

ジャッジ（問題側の相手役のプログラム）と解答の標準入出力をつないで実行します。

| 言語 | ジャッジを置く場所 |
|---|---|
| Rust | `examples/<バイナリ名>_judge.rs`（バイナリが 1 つなら `examples/judge.rs`） |
| C++ | `examples/judge.cpp`（`examples/main_judge.cpp` でも可） |
| Python | `examples/judge.py`（`main_judge.py` でも可） |

- 「対話テスト」を押すと実行します。テストのフォルダに `interactive-N.in` があれば、そのパスがジャッジの第 1 引数として渡されます（なければ引数なしで 1 回だけ実行）。
- やり取りの内容は「テスト結果」に時系列で表示されます。
- 解答は、出力するたびに flush してください（しないと、ジャッジが待ち続けてしまうことがあります）。

| 判定 | 条件 |
|---|---|
| AC | 両方が終了コード 0 で終わった |
| WA | ジャッジが 0 以外で終わった |
| RE | 解答が異常終了した |
| TLE | 全体で `timeLimitMs` を超えた |
| MLE | 解答のメモリが `memoryLimitMiB` を超えた |

## デバッグ

1. エディタの行番号の左側をクリックするか F9 で、ブレークポイントを置きます。
2. 「デバッグ」（F5）を押します。`input.txt`（「テスト結果」の「このケースをデバッグ」から始めた場合はそのケースの入力）が標準入力になります。
3. サイドバーが「実行とデバッグ」に切り替わります。止まったときにはその行が強調されて、変数・ウォッチ式・コールスタック・ブレークポイントが表示されます。

| 操作 | キー |
|---|---|
| 続行・一時停止 | F5 |
| ステップオーバー | F10 |
| ステップイン | F11 |
| ステップアウト | ⇧F11 |
| 停止 | ⌘. |

- panic が起きたときにも止まります。
- 下の「デバッグコンソール」では、式や LLDB のコマンドを入力できます（あなたの権限で実行されます）。
- デバッグ中のプログラムは、IDE に許可した「書類」フォルダなどへのアクセス権を引き継いで動きます（問題ごとに macOS の確認が出ないようにするためです）。
- デバッグは最適化なし（dev）でビルドして実行します。ジャッジ（release）とは、実行速度やオーバーフロー時の挙動が異なります。

### C++ のデバッグ

- `g++ -g -O0 -D_GLIBCXX_ASSERTIONS` でビルドし（フォルダ内の `target/main-debug`）、`vector` や `string` も含めて変数の中身を確認できます。
- ブレークポイントは `.cpp`・`.hpp`・`.h` などに置けます。
- panic の代わりに、例外が投げられたとき（`throw`）と `abort` で止まります。
- `-D_GLIBCXX_ASSERTIONS` により、`vector` の範囲外アクセスなども `abort` として検出されます（実行・サンプルテスト・提出用のビルドには付けません）。
- 止まったときは、作業領域内のソースのうち、いちばん上のフレームが選ばれます。
- デバッグコンソールに LLDB の「`DW_TAG_member '_M_local_buf' refers to type …`」という警告が出ることがあります。GCC のデバッグ情報を LLDB が読むときのもので、変数の表示には影響しません。

### Python のデバッグ

- debugpy を使い、設定の処理系（CPython・PyPy のどちらでも）で実行します。ブレークポイントは `.py` に置けます。
- 捕まえていない例外（`KeyError`・`IndexError` など）が起きると、その行で止まります。`exit()`・`sys.exit()` では止まりません。
- debugpy の上で動かすため、通常の実行よりかなり遅くなります。
- デバッグコンソールでは Python の式を入力できます（LLDB のコマンドは使えません）。

**debugpy のインストール**

IDE がインストールすることはありません。初めてデバッグするときにインストールのコマンドが実行ログに表示されるので、ターミナルで実行してください（処理系ごとに、アプリのフォルダの `python/cpython`・`python/pypy` にインストールします）。例：

```sh
"/opt/homebrew/bin/python3.13" -m pip install --target "$HOME/Library/Application Support/io.github.ishigaki892.acdstudio/python/cpython" debugpy
```

## エディタと言語サーバー

### 言語サーバー

言語サーバーは一度に 1 つだけ動くので、言語の違うファイルを行き来すると再起動します。調子が悪いときは、メニューの「ファイル」→「言語サーバーを再起動」を試してください。

#### Rust（rust-analyzer）

- `.rs` ファイルを開くと rust-analyzer が起動し、補完・診断・ホバー・インレイヒントが使えます。
- 「コンテストを作る」で作ったコンテストのフォルダでは、その中の問題をまとめて扱うので、同じコンテストの問題を行き来しても再起動しません（問題を追加したときは再起動します）。

#### C++（clangd）

C++ のフォルダ（`main.cpp` のあるフォルダ）の `.cpp`・`.hpp`・`.h` などを開くと clangd が起動し、Rust と同じ機能が使えます。

- **必要なもの**：Xcode Command Line Tools の clangd（`xcode-select --install` でインストール）と、ビルドに使う g++（[C++](#c)）。
- IDE が clangd に、ビルドと同じオプション（`-std=gnu++23`・`-DATCODER`・AC Library の場所など）を渡します。標準ヘッダーは使用する g++ のものを読むので、`#include <bits/stdc++.h>` もエラーになりません。
- `<コンテスト>/<問題>/` の形のフォルダでは、同じコンテストの C++ の問題をまとめて扱います。
- clangd はフォルダ内にインデックス（`.cache/`）を作らず、`.clangd` の設定ファイルも読みません。
- 整形スタイルは `.clang-format` で決まります。C++ でコンテストや問題を作ると、コンテストのフォルダに置かれます（LLVM スタイル、インデント 4）。`.clang-format` がないフォルダでは clangd の既定（インデント 2）になります。

#### Python（basedpyright）

Python のフォルダ（`main.py` のあるフォルダ）の `.py` を開くと basedpyright が起動し、補完・診断・ホバー・インレイヒント・定義ジャンプ・参照検索が使えます。

- **必要なもの**：basedpyright（`brew install basedpyright`）。IDE がインストールすることはありません。
- 設定の処理系（[Python](#python)）のバージョンで解析します。型チェックの強さは basedpyright の `standard`（pyright の既定）で、開いているファイルだけを解析します。
- `<コンテスト>/<問題>/` の形のフォルダでは、同じコンテストの Python の問題をまとめて扱います。
- basedpyright には整形機能がないため、整形（⇧⌥F や ⌘S 時の整形）はしません。⌘S は保存だけです。

### 移動と整形

- 定義へジャンプ（F12）、参照検索（⇧F12。Esc で閉じる）、整形（⇧⌥F。⌘S でも整形してから保存）が使えます。
- 次のようなファイルへジャンプした場合は、読み取り専用のタブで開きます。
  - Rust：標準ライブラリや依存クレート
  - C++：標準ヘッダー（使用する g++ と SDK のもの）と AC Library
  - Python：型情報（basedpyright 付属の typeshed の `.pyi`）・標準ライブラリ・site-packages（設定の処理系のもの）・自作のモジュール（`libraries/python/`）

### タブ

- 同じ名前のファイルを複数開くと、タブに区別できるフォルダ名（例：`…/abc339_a`）が付きます。フルパスは、タブにマウスを乗せると表示されます。
- タブが並びきらないときは、タブの列の上でホイールを回すと横にスクロールできます。

### パンくずリスト

タブの列の下に、作業領域からのフォルダの道筋とファイル名、カーソル位置の記号とそれを囲む記号が表示されます（例：`abc480 › a › src › main.rs › impl Foo › bar`）。

- 記号の情報は言語サーバー（rust-analyzer・clangd・basedpyright）から取得し、編集が止まってから 0.5 秒ほどで更新されます。言語サーバーが動いていないとき（信頼していないフォルダなど）は表示されません。
- Markdown（`.md`）では見出しを表示します（`#` で始まる行だけ。コードブロック内は除きます）。
- 各段を押すと一覧が表示されます。↑↓ で選び、Enter で決定、Esc で閉じます。
  - フォルダの段：そのフォルダの中身
  - ファイルの段：同じフォルダの中身（フォルダを選ぶとその中身に切り替わり、ファイルを選ぶと開きます）
  - 記号や見出しの段：同じ階層の記号・見出しの一覧（選ぶとその場所に移動）
- 読み取り専用のタブではファイル名だけを表示します。
- パンくずリストは設定の「表示」で非表示にできます。

### 見た目

- 行頭のインデントは、1 段（4 スペースまたはタブ 1 つ）ごとに薄い色で塗り分けられます。
- エラーや警告のある行は背景に色が付き、行末にメッセージが表示されます（いちばん重要度の高いもの。ほかにもあれば「（ほか N 件）」）。

### 保存

- ファイルは自動で保存されます（⌘S ですぐに保存）。
- ほかのアプリでファイルが変更されたときは、「再読み込み」するか「上書き」するかを聞かれます。
- 保存できないファイル（ほかのアプリで削除された、書き込み権限がないなど）があると、タブを閉じる・アプリを終了する・別のフォルダを開くときに、変更を破棄するかを確認されます。

## スニペット

アプリのフォルダ（[データの場所](#データの場所)）にある言語ごとのファイルに、VS Code と同じ形式でスニペットを書くと、その言語のファイルで使えます（ほかの言語のファイルには出ません）。コメント（`//`・`/* */`）や末尾のカンマも書けます。

| 言語 | ファイル | 使えるファイル |
|---|---|---|
| Rust | `snippets-rust.json` | `.rs` |
| C++ | `snippets-cpp.json` | `.cpp`・`.hpp`・`.h` など |
| Python | `snippets-python.json` | `.py` |

```json
{
  "入力を読む": {
    "prefix": ["rd", "読む"],
    "body": ["let ${1:n}: usize = sc.next();", "$0"],
    "description": "1 つ読む"
  }
}
```

**使い方**

- `prefix` の文字を入力すると、補完の候補に ✂ のアイコン付きで表示されます。
- Tab か Enter で展開し、Tab・⇧Tab で入力欄（`$1`・`${1:既定の文字}`）を移動します。最後は `$0` の位置に移ります。
- 2 行目以降は、挿入した行のインデントに合わせます（行頭のタブは 4 スペースになります）。
- 言語サーバーが動いていなくても、信頼していないフォルダでも使えます。

**書き方の注意**

- 選択肢（`${1|a,b|}`）は最初の候補が既定の文字になります。
- 変数（`$TM_SELECTED_TEXT` など）は空になります。
- 本文中に文字として `${` や `#{` を書くと入力欄として扱われてしまうため、書けません。

**読み込み**

- IDE のタブで書き換えて保存すると、すぐ読み込み直します（ほかのアプリで書き換えたときは、IDE のウィンドウに戻ったときに読み込み直します）。
- 読み込めない項目があればその名前をお知らせします（ほかの項目は使えます）。JSON として読めないときは、以前のスニペットを使い続けてお知らせします。
- 以前のバージョンの `snippets.json` は、`snippets-rust.json` がなければ、IDE が読み込むときに `snippets-rust.json` へ名前を変えます。

**設定画面の「スニペット」**（⌘,）

- 言語ごとに、今読み込めているスニペットの一覧が表示されます。
- 「ファイルを開く」で、その言語のファイルを IDE のタブで開きます（なければ空のファイルを作ります）。
- 「VS Code から取り込む」で、VS Code のスニペット（`~/Library/Application Support/Code/User/snippets/` の `rust.json`・`cpp.json`・`python.json`）を、対応する言語のファイルにコピーします。
  - 確認ダイアログが出たあと、今のファイルは同じフォルダに `snippets-rust.backup-<時刻>.json`（C++ は `snippets-cpp.backup-…`、Python は `snippets-python.backup-…`）として退避されます（言語ごとに新しいものから 5 つまで残します）。
  - VS Code のファイルを自動で読み込むことはありません。

## 提出

### ログイン

右下の「提出結果」の「ログイン」を押すと、AtCoder のログイン用のウィンドウが開くので、そこでログインしてください。パスワードが IDE に渡ることはありません。ログインのセッションは macOS のキーチェーンに保存します。

### 提出の流れ

開催中のコンテストの問題で「提出」を押すと、次の順に進みます。

1. **サンプルテスト**：結果は「テスト結果」に表示されます。すべて AC のときだけ次に進み、AC でないケースがあるときや途中で止めたときは提出しません。サンプルがない問題（インタラクティブ問題など）では、テストをせずに次に進みます。
2. **提出前のチェック**：送るソースを調べます（[提出前のチェック](#提出前のチェック)）。
3. **確認ダイアログ**：「提出する」を選んだときだけ提出します。
4. **判定**：「提出結果」に判定が表示され、確定するまで追いかけます（[提出のあと](#提出のあと)）。

- 「提出」のショートカットキーは、初期状態では割り当てていません（[キーの割り当て](#キーの割り当て)）。
- 開催期間外の問題は提出しません（[開催期間外の問題](#開催期間外の問題)）。

#### 提出する言語

提出ページの選択肢から選びます。見つからないときは提出しません。

| 言語 | 選ぶもの |
|---|---|
| Rust | 「Rust」で始まる最初のもの |
| C++ | 「C++23 (GCC 15.2.0)」 |
| Python | 設定の処理系に応じて「Python (CPython 3.13.7)」か「Python (PyPy 3.11-v7.3.20)」（Codon は選びません） |

### 提出前のチェック

提出と「コードをコピー」のときは、別のファイルに分けたコード（Rust の `mod` と自作のライブラリ、C++ のヘッダー、Python の自作のモジュール）を、1 つのファイルにまとめます。チェックでは、まとめられないものや、ジャッジで動かないものを調べて注意を出します。

| 言語 | チェックする内容 |
|---|---|
| Rust | 展開できない `mod`（ファイルが見つからないもの・`#[path]` の付いたもの）、展開したモジュールの中の `include!` など、ジャッジにないクレート（自作のライブラリが使うクレートも）、バージョンの違い、バイナリ名と問題の記号の食い違い、展開できない自作のライブラリ（proc-macro・`build.rs` のあるもの） |
| C++（`main.cpp`） | 見つからないので展開できないヘッダーを読む `#include "…"`（見つかるものは展開します。[C++](#c)）、手元の GCC のバージョンがジャッジ（15.2.0）と違うこと |
| Python（`main.py`） | `main.py` の中の相対 `import`（埋め込めません）、ジャッジの言語一覧にないパッケージの `import`（自作のモジュールの中のものも）、標準ライブラリと同じ名前の自作のモジュール（`heapq.py` など。埋め込みません）、手元の処理系のバージョンがジャッジ（CPython 3.13.7・PyPy 7.3.20）と違うこと |

- C++ でヘッダーを展開したときは、確認ダイアログに展開したヘッダーが表示され、表示される大きさは展開したあとのものです。
- Python の補足：
  - PyPy は CPython よりパッケージが少なく、`numba` などがありません。
  - `import` は手元の処理系で解析します（文字列やコメントの中は数えません）。処理系が見つからないときは、チェックできなかったことを注意として表示し、自作のモジュールは埋め込みません。
  - ジャッジのパッケージは、言語一覧のパッケージ名を `import` の名前に読み替えて比べます（`scikit-learn` は `sklearn`、`ac-library-python` は `atcoder`、`z3-solver` は `z3` など）。
  - 一覧にはないものの、ほかのパッケージの依存として入っているもの（PyPy の `dateutil` など）にも注意が出ることがあります。

#### Rust の `mod` の展開

提出と「コードをコピー」のとき、`mod geo;` のように別のファイルを読むモジュールの宣言を、`mod geo { <geo.rs の中身> }` に置き換えて 1 つのファイルにします（中身は書き換えません）。

- ファイルは Rust の決まりどおりに探します。
  - `src/main.rs`・`src/bin/a.rs` の中の `mod geo;` は、同じフォルダの `geo.rs` か `geo/mod.rs`
  - `geo.rs` の中の `mod point;` は、`geo/point.rs` など
- 入れ子も展開し、中身の前後に `// ---- 展開：src/geo.rs ----` のコメントが入ります。
- 確認ダイアログに展開したモジュールが表示され、表示される大きさは展開したあとのものです。
- 文字列やコメントの中の `mod x;` は数えません。
- `geo.rs` と `geo/mod.rs` の両方があるときは送りません。展開したあとが 512 KiB を超えるときも送りません。

#### Rust の自作のライブラリ

**置き方と使い方**

1. アプリのフォルダの `libraries/rust/` に、ふつうのライブラリのクレートを置きます（`libraries/rust/` で `cargo new --lib mylib` のように作ります）。フォルダは、設定画面の「テンプレート」の「ライブラリのフォルダを開く（Rust）」で開けます。
2. 問題の `Cargo.toml` の `[dependencies]` に `mylib = { path = "<アプリのフォルダ>/libraries/rust/mylib" }` を書きます。写して使う行は、設定画面の「テンプレート」に表示されます。

- 手元ではふつうの依存として使えます（rust-analyzer の補完も効きます）。
- `templates/dependencies.toml` に書けば、作る問題すべてに入ります。

**提出と「コードをコピー」のとき**

main から使っているライブラリを、main.rs の後ろに `mod mylib { … }` として入れます（ライブラリの中の `mod x;` も展開します）。

- 次のように書き換えます。文字列やコメントの中は書き換えません。
  - ライブラリの中の `crate::` を `crate::mylib::` に
  - ライブラリの中の `$crate` を `$crate::mylib` に
  - main の中の `mylib::`（パスの頭）を `crate::mylib::` に
  - `#[macro_export]` のマクロは `mylib::m!` の形で使えるように
- ライブラリが `libraries/rust/` のほかのライブラリを使っていれば、それも入れます。使っていないライブラリは入れません。
  - `libraries/rust/` のパスの依存には、使っていなくても「ジャッジでは使えません」の注意は出さないので、確認ダイアログを省く設定も効きます。
- 確認ダイアログに「ライブラリ mylib（src/lib.rs・…）」と表示されます。
- ライブラリが使うクレートも、ジャッジにあるかを確認します。proc-macro のクレート・`build.rs` のあるクレートは入れません（注意が出ます）。

**限界**

次のものには対応していません。

- ライブラリの中で `#[macro_export]` のマクロを、定義より前で名前だけで呼ぶこと
- `#[macro_use]`
- ライブラリと main（edition 2024）で edition が違うときの書き方の違い

#### Rust の送る前のビルドの確認

`mod` や自作のライブラリを展開したときは、送る前に、展開したものをパッケージの `target/atcoder-studio-check/` の作業用のパッケージでリリースビルドして確認します（サンプルテストでビルドした依存を使い回すので、ふつうは数秒です）。

エラーがあれば送らず、エラーを表示します（`src/main.rs` の行番号は展開したあとのものです）。

#### Python の自作のモジュールの埋め込み

提出と「コードをコピー」のとき、`main.py` から `import` をたどり、`main.py` のフォルダか `libraries/python/` にあるモジュール（パッケージ・中のモジュール・相対 `import` で読むものも）のソースを、`main.py` に文字列として入れます。入れたソースは、Python の `import` の仕組み（`sys.meta_path`）で読ませます。

- 入れる場所は `main.py` の先頭です（説明の文字列と `from __future__ import …` があれば、その後ろ）。
- `import mylib`・`from mylib.seg import Seg` などの書き方はそのまま動きます。
- 入れたところの前後に `# ---- 展開：自作のモジュール（…）----`・`# ---- 展開ここまで ----` のコメントが入ります。
- 確認ダイアログに「mylib（libraries/python/mylib/__init__.py）」のように展開したモジュールが表示され、表示される大きさは埋め込んだあとのものです。

**送る前の確認**

- 入れたモジュールをすべて読み、埋め込んだ `main.py` を手元の処理系で `compile()` して構文を確認します（動かしはしません）。
- 構文エラーがあれば送らず、ファイルと行を表示します。
- 埋め込んだあとが 512 KiB を超えるときも送りません。

**限界**

- `importlib.import_module` や `__import__` で名前を組み立てて読むものはたどりません。
- 埋め込んだモジュールの `__file__` は本物のファイルではなく `<mylib>` のような名前で、エラーの行番号は元のファイルのものです。

### 提出の設定

設定画面の「提出」で、次の 2 つを変更できます（[設定](#設定)）。

**提出前のサンプルテスト**（初期状態はオン）

- オフにすると、テストをせずに次に進みます。
- サンプルテストに通ったかどうかは、IDE が実行履歴で確認します。

**確認ダイアログ**（初期状態は表示）

表示しない設定にしても、ダイアログを省くのは、今のソースでサンプルテストがすべて AC になっていて、提出前のチェックで注意がないときだけです。次のいずれかなら表示します。

- サンプルがない
- 目視確認のケースがある
- テストのあとにファイルを変えた（提出するファイルのほか、Rust の展開したモジュール〔入れ子も〕、C++ の展開したヘッダー〔`libraries/cpp/` のものも〕、Python の同じフォルダの `.py` も見ます）
- 注意がある

省いたときは、実行ログに「確認のダイアログを省いて提出しました」と表示されます。表示しない設定で保存するときは、OS の確認が出ます。

### 提出のあと

- 「提出結果」に判定が表示され、確定するまで追いかけます。「更新」で読み込み直し、「詳細」で公式の詳細ページを開けます。
- 判定を一時的に読み込めないとき（混雑しているときなど）は、5 秒ずつあけて 3 回まで読み直し、それでも読めなければ追いかけるのをやめます。
- 提出後の提出 ID は、「自分の提出」ページのその問題のいちばん新しいものです。それが IDE から前に出した提出と同じときは、もう 1 回だけ読み込み、それでも同じなら（今回の提出がまだ載っていないので）、取り違えないように「提出 ID を決められませんでした」と表示します。

### 開催期間外の問題

開催期間外の問題は提出しません。代わりに「コードをコピーして公式の提出ページを開く」で、ブラウザから提出できます。

- C++ ではヘッダーを、Rust では `mod` と自作のライブラリを、Python では自作のモジュールを、提出と同じく展開したものをコピーします。
- 文法・ビルドの確認はしません。Python は処理系が見つからなければ、そのままコピーします。

### コンテストの提出状況

アクティビティバーの「コンテスト」（旗のアイコン）で、問題文の欄に表示している問題のコンテストについて、問題ごとの提出状況を表示します。開いているファイルを切り替えて問題が変われば、コンテストも切り替わります。

| 印 | 意味 |
|---|---|
| ✓（緑） | AC した提出がある |
| ✗ | 提出はあるが AC していない（最後の判定と提出回数を表示） |
| ・ | まだ提出していない |

- ログインしていないときは「ログイン」ボタンが表示されます。
- 読み込めなかったときは理由が表示され、前回の結果はそのまま残ります。
- 「自分の提出を開く」で、公式ページを既定のブラウザで開きます。

#### 読み込み

- AtCoder の「自分の提出」ページ（そのコンテストの分だけ）を、ログインのセッションで読み込みます。
- 読み込むのは、次のときだけです。
  - 「コンテスト」を開いたとき（前回から 1 分以上たっていれば）
  - コンテストが切り替わったとき
  - 「更新」を押したとき
  - ログインしたとき
- ページは 1 秒ずつ間隔をあけて、新しい順に 10 ページまで読みます（それを超える場合はお知らせします）。
- IDE から提出したものは、通信せずに一覧に反映します（判定を追っている間の状態も表示します）。

#### 順位・予想 perf・diff

続けて、そのコンテストの順位表を読み込み（「自分の提出」と 1 秒あけて 1 回だけ）、次のものを表示します。順位表の中身は計算に使うだけで、保存しません。コンテストが始まる前は読み込みません。

| 項目 | 内容 |
|---|---|
| 順位 | 全体の順位と、Rated の参加者の中での順位（同順位は平均）。参加していなければ「参加していません」と表示します |
| 予想 perf | 今の順位から計算したパフォーマンスです |
| diff | 各問題の行の「diff」。AtCoder Problems に難易度がある問題（終わったコンテスト）はそれを、ない問題（開催中・終わった直後など）は予想 diff を表示します |
| 予想 diff | AtCoder Problems と同じ方法で順位表から推定した難易度（50% の確率で解けるレート）です |

- **予想 perf の精度**：各参加者の APerf を、順位表のレートと参加回数から逆算した近似で計算するので、公式の値とずれることがあります（ABC481 では、公式 1259 に対して 1275）。開催中は、順位と参加者が変わるので値も変わります。
- **予想 diff の精度**：開催中は、まだ解いていない人も「解けなかった」側に数えるので、高めに出て、時間とともに下がります。使える参加者が 40 人より少ない問題・まだ誰も解いていない問題には出ません。
- **色**：予想 perf と予想 diff の数字は、AtCoder のレートの色（400 ごとに灰・茶・緑・水・青・黄・橙・赤）で表示します。暗い背景で読めるように、公式の色より明るくしています。
- **出さないコンテスト**：Rated でないコンテストと AHC（ヒューリスティック）では、予想 perf と予想 diff は出さず、理由を表示します。ヒューリスティックかどうかは、コンテスト ID が `ahc` で始まるか、コンテスト名に「Heuristic」「ヒューリスティック」が入っているかで判断します。
- 順位表だけ読み込めなかったときは理由を表示し、前回の順位などはそのまま残します。
- 読み込んだ順位表から、右下の「追跡」の表も新しくします（[追跡するユーザー](#追跡するユーザー)。通信は増えません）。

#### 行を押したとき

- その問題のフォルダ（`<コンテスト>/<問題 ID>/`）の `src/main.rs`（C++ は `main.cpp`、Python は `main.py`）を開きます。開いたファイルのフォルダから問題が決まるので、問題文の欄もその問題に切り替わります。
- 複数の言語のファイルがある場合は、Rust → C++ → Python の順で選びます。
- フォルダがない場合（まだ問題を作っていない、作業領域を開いていないなど）は、問題文の欄でその問題を選びます。フォルダから決まった問題と結び付いている場合は、結び付きを外してその問題を表示します（問題の選択欄の「フォルダの問題に戻す」で戻せます）。

### 追跡するユーザー

設定の「追跡」に AtCoder の ID を書いておくと（1 行に 1 人、30 人まで）、右下の「追跡」のタブに、問題文の欄の問題のコンテストの順位表から、自分と追跡するユーザーの行を表示します。開催中のコンテストでも、終わったコンテストでも使えます。

#### 追跡の表の見方

| 列 | 内容 |
|---|---|
| # | 追跡している人（自分を含む）の中での順位です。提出のある人だけで数え、順位が同じ人は同じ数にします（例：1・2・2・4）。提出のない人と順位表にいない ID は「—」です |
| ユーザー | ID を AtCoder のレートの色で表示します |
| 順位・得点 | 順位は公式の順位表の順位です。得点の右の「(2)」はペナルティ（AC までの誤答）の数、下の時間はペナルティの時間を含む時間です。提出がなければ「提出なし」 |
| 問題ごとのます | 下の表のとおりです。マウスを乗せると、得点・時間・提出の回数を表示します |

| ます | 意味 |
|---|---|
| 緑で経過時間（「分:秒」） | AC。誤答があれば下に「(+2)」 |
| 黄で「−2」 | AC していない（数字は誤答の数） |
| 「…」 | 判定待ちの提出がある |
| 空 | 出していない |

- **並び方**：提出のある人を順位の順に並べ（同じ順位なら自分、次に設定の順）、そのあとに提出のない人、最後に順位表にいない ID を並べます。自分の行は色を付けて「（自分）」と表示します。
- 順位表にいない ID（参加していない・ID の誤り）は「この順位表にいません」と表示します。
- 提出すると、右下は「提出結果」のタブに切り替わります。

#### 読み込みと通信

- 順位表を読み込むのは、次のときだけです。決まった間隔では読み込みません。コンテストが始まる前は読み込みません。
  - 「追跡」の「更新」を押したとき（順位表だけを 1 回。続けて押せるのは 10 秒後）
  - サイドバーの「コンテスト」で読み込んだとき
- 追跡する ID は AtCoder には送りません。読み込んだ順位表（ログインしている人が公式の順位表で見られるもの）から、手元で取り出します。順位表の中身は保存しません。
- ログインしていないときは「ログイン」ボタンが表示されます。
- 自分の行は、ログインしているアカウントの ID が分かれば表示します（分からないときは、AtCoder のトップページを 1 回読んで確かめます）。

## 残り時間と通知

### 残り時間

ツールバーの右端に、今の問題のコンテストの「開始まで 1:23:45」（開始前）・「残り 42:15」（開催中）を表示します。

- 1 時間未満は「分:秒」、24 時間以上は「3 日 4:05:00」の形です。
- 残り 5 分を切ると色が変わります。
- マウスを乗せると、開催期間（例：2026-10-26 21:00〜22:40）を表示します。
- コンテストが終わったあと、問題が決まっていないとき、読み込めなかったときは、何も表示しません。

**開始前のコンテストの時間を出す**

開始前のコンテストは、まだ問題を開けないので、ツールバーの選択欄にコンテスト ID を入れて「一覧」を押してください。

- 一覧は読み込めません（理由が表示されます）が、そのコンテストの時間を表示します。
- 問題を開くと、その問題のコンテストに戻ります。
- フォルダの問題と結び付いているときは、先に「紐付けを外す」を押します。

**開催期間の読み込み**

- 開催期間は、コンテストのトップページ（ログインなしで読めるページ）から、コンテストごとに 1 回だけ読み込み、アプリを開いている間は覚えておきます。
- 残り時間が 0 になったときは、延長に備えて 1 回だけ読み直し、延びていれば数え続けます。
- 時間は Mac の時計で数えます。

### 通知

設定画面の「通知」でオンにすると、次のときに macOS の通知で知らせます。どちらも初期状態はオフで、IDE のウィンドウが手前にないときだけ知らせます。

| 通知 | 知らせるとき |
|---|---|
| 判定 | IDE から提出したものの判定が確定したとき（例：「AC：abc480_c」「C - 問題名・300 点・123 ms・3600 KiB」） |
| コンテストの開始 | ツールバーに残り時間を表示しているコンテストが始まったとき（1 回だけ）。Mac がスリープしていて、始まってから 1 分より後に気づいたときは知らせません |

- オンにして保存すると、テストの通知を 1 回出します。初めてのときは、macOS が通知を許可するかを聞くので「許可」を押してください。
- 通知が出ないときは、システム設定の「通知」で「AtCoder Studio」を許可してください（IDE からは、許可されているかどうかが分かりません）。
- 集中モードの間は、バナーが表示されません。
- 開発用（`npm run tauri dev`）では、通知は「ターミナル」の名前で表示されます。

## 過去問の一覧

サイドバーの「コンテスト」の「過去問の一覧」を押すと、中央に「過去問」のタブが開きます。

- エディタのタブと同じように切り替え・閉じる（⌘W）ことができ、アプリを開き直したときも開いています。
- このタブが手前にあるときは、⌘S は何もしません。

### 表の見方

「ABC」「ARC」「AGC」「AWC」を切り替えると、行はコンテスト（新しい順）、列は問題の記号（A〜G・H・Ex など）の表が出ます。「JOI」は、列とますの中身が少し違います（[JOI](#joi)）。「解き直し」では、解き直しの印を付けた問題の一覧が出ます（[解き直し](#解き直し)）。

| ますの見た目 | 意味 |
|---|---|
| 数字 | AtCoder Problems の難易度（diff）を、AtCoder のレートの色で表したもの。試験的な推定には「?」が付きます |
| 「—」 | 難易度がない問題 |
| 背景が緑 | AC 済み |
| 背景が紫 | AC 済みのうち、問題文の欄で「解説」と記録した問題（解説 AC。[自力 AC・解説 AC の記録](#自力-ac解説-ac-の記録)） |
| 背景が黄 | 提出したが AC していない |
| 右上に水色の小さな三角 | 解き直しの印を付けた問題。説明に「解き直す（付けた日 から）」が出ます |

- 表の上に、AC 数と問題数（解説 AC があればその数）が出ます。
- ますにマウスを乗せると、問題 ID・diff と、AC 状況（「自力 AC」「解説 AC」「AC（自力・解説の記録なし）」「提出あり（AC なし）」）が出ます。AC していない問題に付けた記録も、ここに出ます。
- ますを押すと、その問題を問題文の欄に表示します（フォルダの問題と結び付いているときは、結び付きを外します。問題の選択欄の「フォルダの問題に戻す」で戻せます）。

**AWC について**

「AWC」は AtCoder Weekday Contest です。

- AtCoder Problems に難易度がないので、ますはすべて「—」で、AC 状況は背景の色で分かります。
- ほとんどの回は A〜E ですが、問題の多い回（awc0100・awc0150 は A〜O）があるので、列は O まであります（横にスクロールできます）。
- 新しい回が表に出るのは、AtCoder Problems のデータに入ってからです。

### JOI

「JOI」を押すと、表の上に小分けの切り替えが出ます。選んだ小分けは、アプリを開き直しても残ります。

| 小分け | 入るコンテスト |
|---|---|
| 一次予選 | `joi2020yo1a` などの一次予選（第 1〜3 回） |
| 予選・二次予選 | 2019 年までの予選（`joi2006yo` など）と、二次予選（`joi2020yo2` など） |
| 本選 | 2025 年までの本選（`joi2025ho` など）と、セミファイナルステージ・ファイナルステージ（`joi2026sf`・`joi2026final`） |
| 春合宿 | 春合宿・春季トレーニング（`joisc2007`・`joisc2013-day1`・`joisp2025` など） |
| JOI Open | JOI Open Contest（`joiopen2025` など） |
| JOIG | JOIG のコンテスト（`joig2025-open`・`joigsp2025`・`joig2026final` など） |
| その他 | どれにも当てはまらない、`joi` で始まるコンテスト（あるときだけ出ます） |

- **列**：「1・2・3 …」で、その回の何問目かです。JOI は回によって問題の記号が違う（`A`〜`L`、`1`〜`5`、`K1`〜`K6`、古い春合宿の `anagram` などの英単語）ので、記号ではなく順番で並べます。回の中は記号の順（数字の部分は数として比べます）です。
- **ます**：JOI の問題には AtCoder Problems の難易度がないので、diff の代わりに問題の記号を出します。長い記号は途中で切れます。マウスを乗せると、問題 ID と記号の全部が出ます。
- AC 状況の色、自力・解説の記録、解き直しの印は、ほかの表と同じです。
- 出力だけを提出する問題や、通信の問題など、JOI 独自の形式の問題は、サンプルテスト・対話テストでできる範囲でしか試せません。

### AC 状況に使う ID

- 設定画面の「過去問」に書いた AtCoder の ID を使います。
- 空なら、ログインしているアカウントの ID を使います（アプリを開き直したあとで ID が分からないときは、AtCoder のトップページを 1 回読んで知ります）。
- どちらもなければ、AC 状況は出さず diff だけを表示します。

### データの読み込み

データは AtCoder Problems（https://kenkoooo.com/atcoder/ 。AtCoder とは別の人が運営している非公式のサービス）から読み込みます。

- 読み込みは 2 秒ずつ間隔をあけ、ログインのセッションは送りません。
- AC 状況のために、AtCoder の ID を AtCoder Problems に送ります（公開されている提出を読みます）。
- コンテスト・問題・難易度のデータは、アプリのフォルダの `atcoder-problems/` に保存し、保存から 24 時間たつまでは読み直しません。「更新」を押すと読み直します。
- 提出は、前回の続きだけを読み込みます（タブを開いたときは前回から 1 分以上たっていれば、「更新」では毎回）。
  - 1 回に読むのは 500 件ずつ 20 回（1 万件）までで、それより多いときは、続きを次の「更新」で読みます。
  - 新しい提出が AtCoder Problems に反映されるまでには、5 分ほどかかります。
- 読み込めなかったときは、保存してあるもので表を出し、理由を表示します。

### 自力 AC・解説 AC の記録

問題文の欄の制限の行の下（右寄せ）にある「自力」「解説」を押すと、その問題をどう解いたかを記録します。押されているほうをもう一度押すと、記録を外します。

- どの問題にも付けられます（AC していない問題にも付けられます。AtCoder Problems に AC が反映される前に付けておけます）。
- 記録は問題 ID ごとです。ABC と ARC の共通の問題のように 2 つのコンテストにある問題は、両方の表に同じ記録が出ます。
- 記録はアプリのフォルダの `problem-marks.json` に保存します。AtCoder・AtCoder Problems には送りません。
- ファイルを読めなかったときは、別の名前で退避し、記録なしで始めます（そのことをお知らせします）。

### 解き直し

#### 印を付ける

問題文の欄の制限の行の下（右寄せ）の「解き直す」を押すと、その問題に解き直しの印を付けます（付けた日も覚えます）。もう一度押すと外します。

- 「自力」「解説」とは別で、「解説」を付けても印は付きません。
- 記録は `problem-marks.json` に入ります。

#### 一覧

「過去問」のタブの「解き直し」に、印を付けた問題が、付けた日の新しい順に並びます。

- 問題（コンテストと記号。ABC と ARC の共通の問題のように 2 つのコンテストにある問題は両方）・diff・AC 状況・自力／解説・付けた日が出ます。
- 行を押すとその問題を問題文の欄に表示し、「外す」で印を外します。
- 一覧は、AtCoder Problems のデータと AC 状況を、保存してあるものだけで作ります（新しく読みません）。コンテスト・記号・diff・AC 状況は、「ABC」などの表を一度開いて読んだあとに出ます。
- 問題名は出しません。

#### 白紙から解き直す

問題のフォルダ（例：`abc480/abc480_a`）のファイルを開いて、問題文の欄の「…」→「白紙から解き直す」を押すと、確認のあとで次のことをします。

1. 保存していない変更を保存する
2. `src/main.rs`（C++ は `main.cpp`、Python は `main.py`）を、そのフォルダの `old/main-年月日-時分秒.rs` に移す（同じ名前があれば `-2` などを付け、上書きしません）
3. `main` を、「この問題を作る」と同じ中身（テンプレートと、設定に従って入力のコード）で書き直し、開いているタブを読み直す

- **変えないもの**：`test/`（サンプル・足したテストケース）・`Cargo.toml`・`compile_flags.txt`・`examples/`（生成器・愚直解）と、解き直しの印。
- **押せるとき**：開いているファイルのフォルダから問題が決まっているときだけです（選択欄で選んだ問題では押せません）。Rust で `src/bin/` にファイルがあるフォルダでは使えません。
- **入力のコード**：保存してある問題文から作ります。問題文が保存されていなければ（問題文を一度も表示していなければ）、テンプレートのまま書いて知らせます。
- **`old/` のファイル**：ビルド・提出・「コードをコピー」には入りません（main から使っていなければ）。

### 割り当てを変える

割り当ては、設定画面か、アプリのフォルダの `settings.json` の `keyBindings` で変更できます（[設定](#設定)）。

- 一覧に書いたコマンドはその割り当てを、書いていないコマンドは既定の割り当てを使います。
- 変更は、IDE のウィンドウに戻ったときに反映されます（再起動は不要です）。

1 つの割り当ての書き方（`meta` は ⌘、`alt` は ⌥）：

```json
{ "command": "submit", "key": "enter", "meta": true, "ctrl": false, "alt": false, "shift": true }
```

- `key` にはキーの名前を書きます（英字は小文字。例：`r`、`.`、`f12`、`enter`）。⌥ を使う割り当ては、英字・数字ならキーの位置でも判定します。
- キーの割り当てを外すときは `"key": ""` と書きます（既定の割り当ても使わなくなります）。
- 読めない割り当てや、存在しないコマンドは無視され、ファイル一覧の下にお知らせが表示されます。
- 同じキーを 2 つのコマンドに割り当てたときもお知らせが出ます（一覧で先に書いたほうが使われます）。
- ファンクションキーは、macOS の設定によっては、そのまま押すと画面の明るさ調整などになることがあります。その場合は fn キーを押しながら押してください。

## 設定

⌘,、メニューの「AtCoder Studio」→「設定…」、またはアクティビティバーの下の歯車で、設定画面が開きます。

設定画面には、窓に重ねる「設定1」（既定）と、中央のタブに開く VS Code 風の「設定2」の 2 つの形があり、「表示」の「設定の画面」で選べます（[設定2（VS Code 風の設定画面）](#設定2vs-code-風の設定画面)）。

| 分類 | 内容 |

- ほかのコマンドと同じキー
- ⌘・⌃・⌥ を含まないキー（F1〜F20 は使えます）
- macOS やメニューで使うキー（⌘C・⌘Z など）

**「テンプレート」にあるもの**

- 雛形のファイル（`templates/main.rs`・`templates/dependencies.toml`・`templates/main.cpp`・`templates/main.py`）があるかどうか

- Rust の自作のライブラリの「ライブラリのフォルダを開く（Rust）」（`libraries/rust/`）と、写して使う依存の行（[Rust の自作のライブラリ](#rust-の自作のライブラリ)）
- Python の自作のモジュールの「ライブラリのフォルダを開く（Python）」（`libraries/python/`。[Python](#python)）

### 保存（設定1）

色と表示は、変更するとすぐ画面に反映されます。「保存」で `settings.json` に書き込み、「キャンセル」（または Esc）で元に戻ります。

- 保存で書き換えるのは、キー・色・表示・問題文・提出・通知・過去問・追跡の項目と、Python の処理系の選択だけです。`settings.json` に自分で書いたほかの項目はそのまま残ります。
- キーは、すべてのコマンドの割り当てを書き出します（同じコマンドに 2 つ以上書いていた場合は、先のものだけになります）。
- 設定画面を開いている間に `settings.json` が外部で変更された場合は、画面の内容が読み込み直されます（保存はしません）。

### 設定2（VS Code 風の設定画面）

「表示」の「設定の画面」を「設定2」にして保存するか、設定1の右上の「設定2で開く」を押すと、設定を中央の「設定」のタブで開くようになります。

- エディタのタブと同じように切り替え・閉じる（⌘W）ことができ、アプリを開き直したときも開いています。
- **検索**：上の「設定の検索」に文字を入れると、項目の名前・説明・`settings.json` の名前（例：`editor.fontSize`）に合う項目だけが残ります。キーの割り当てはコマンドの名前とキー（例：`⌘R`）でも、色は色の名前でも絞り込めます。
- **分類**：左の分類を押すと、右がその見出しまで移ります。右をスクロールすると、今いる分類が左で示されます。
- **変えるとすぐ保存します**（「保存」「キャンセル」はありません）。色と表示はすぐ画面に反映され、`settings.json` には、変えるのが止まってから 0.5 秒ほどで書き込みます。
- 提出の確認のダイアログを出さないようにしたときの OS の確認は設定1と同じく出て、キャンセルすると元に戻ります。
- 設定1に戻すときは、右上の「設定1で開く」を押すか、「設定の画面」を「設定1」にします。

### settings.json を直接書く

設定画面の「JSON で開く」で、`settings.json` を IDE のタブで開けます（設定1からは、今の変更を保存して設定画面を閉じてから開きます）。

- ほかのタブと同じく自動で保存し、保存するとすぐ反映されます。
- JSON の書き方が崩れているときは今の設定のまま動き、ファイル一覧の下にお知らせが表示され、エディタでも誤りの場所に印が付きます（直して保存すれば反映されます。崩れている間は、設定画面から保存できません）。
- ほかのアプリで書き換えたときは、IDE のウィンドウに戻ると反映されます。
- `settings.json` とスニペットのファイルのタブは、パンくずリストに「アプリのフォルダ」と表示されます。ブレークポイントは付けられず、アプリを開き直したときには戻りません。

書き方の例（書かなかった項目は既定値になります）：

```json
{
  "version": 1,
  "keyBindings": [ … ],
  "colors": { "indent-rainbow-1": "rgba(255, 255, 64, 0.25)", "syntax-keyword": "#ff8080" },
  "editor": { "indentRainbow": true, "errorLens": true, "breadcrumbs": true, "fontSize": 13 },
  "problem": { "fontSize": 13, "buttons": ["makeInput", "saveSamples"], "mainLoop": false, "fillInput": false },
  "submit": { "testBeforeSubmit": true, "confirmDialog": true },
  "notify": { "judge": false, "contestStart": false },
  "atcoderProblems": { "user": "" },
  "standings": { "follow": ["chokudai"] }
}
```

読み取れない項目は既定値を使い、お知らせが表示されます。

| 項目 | 内容 |
|---|---|
| `colors` | 色の名前と CSS の色（`#rrggbb`、`rgba(…)` など）。名前は `src/styles/tokens.css` の色の変数名から先頭の `--` を除いたものです（例：`bg-base`、`syntax-keyword`、`indent-rainbow-1`、`lens-error-line`）。書いた色だけが変わります |
| `editor.indentRainbow`・`editor.errorLens`・`editor.breadcrumbs` | インデントの色分け、診断のある行の色とメッセージ、パンくずリストのオン／オフ |
| `editor.fontSize`・`problem.fontSize` | エディタと問題文の欄の文字の大きさ（8〜32 の整数、px） |
| `editor.settingsUi` | 設定の画面の形（`dialog`：設定1、`editor`：設定2〔VS Code 風〕） |
| `problem.buttons` | 問題文の欄の見出しに並べるボタン（下の表）。表示される順番は書いた順ではなく、表の順です |
| `problem.fillInput` | 「コンテストを作る」「この問題を作る」のときに、`input!`（C++・Python では入力のコード）を入れておくか（[input! を作る](#input-を作る)） |
| `problem.language` | 問題やコンテストを作るときの言語（`rust`・`cpp`・`python`） |
| `problem.mainLoop` | テストケースが複数のとき、入力の置き換えで `main()` に `for`（Rust なら `input!` と `for _ in 0..t { solve(); }`）まで書くか（[input! を作る](#input-を作る)） |
| `submit.testBeforeSubmit`・`submit.confirmDialog` | 提出前のサンプルテストと確認ダイアログ（[提出の設定](#提出の設定)）。手で `confirmDialog` を `false` にした場合、OS の確認は出ません |
| `notify.judge`・`notify.contestStart` | 判定・コンテストの開始の通知（[通知](#通知)）。手で `true` にした場合、テストの通知は出ません |
| `atcoderProblems.user` | 過去問の表の AC 状況に使う AtCoder の ID（英数字と `_`、16 文字まで。[過去問の一覧](#過去問の一覧)）。空なら、ログインしているアカウントの ID を使います |
| `standings.follow` | 右下の「追跡」に出すユーザーの AtCoder の ID の一覧（30 人まで。[追跡するユーザー](#追跡するユーザー)）。大文字・小文字だけが違う ID は 1 つにまとめます。形が正しくない ID と 31 人目からは使わず、お知らせが表示されます |
| `cpp.compiler` | C++ で使う g++ の絶対パス。空なら自動で探します（[C++](#c)） |
| `python.interpreter` | Python の処理系（`cpython`・`pypy`） |
| `python.cpython`・`python.pypy` | 処理系の絶対パス。空なら自動で探します（[Python](#python)） |

## 既知の制限

### キーが macOS と重なる

- **⌃Space**：エディタで補完を手動で出すキーですが、macOS の「入力ソースの切り替え」と重なっていると、入力ソースが切り替わってしまいます。補完は入力中に自動で出るので普段は困りませんが、手動で出したい場合は、macOS の設定（キーボード → キーボードショートカット → 入力ソース）で切り替えのキーを変更してください。
- **F11**：macOS の機能（デスクトップを表示など）と重なることがあります。ステップインに使う場合は、macOS の設定で外すか、`settings.json` で `stepIn` のキーを変更してください。

### 必要なものが見つからない

| 表示 | すること |
|---|---|
| 「cargo が見つかりません」 | [rustup](https://rustup.rs) で Rust をインストールしてください |
| C++ で「g++-15 が見つかりません」 | ターミナルで `brew install gcc` を実行してください |
| C++ のファイルで「clangd が要ります」 | ターミナルで `xcode-select --install` を実行してください |
| `.py` のファイルで「basedpyright が要ります」 | ターミナルで `brew install basedpyright` を実行してください |

### そのほか

- **ジャッジとの違い**：手元での判定・実行時間・メモリは目安です。ジャッジのバージョン（rustc 1.89.0、edition 2024 など）は、AtCoder の言語アップデートで変わることがあります。
- **提出**：参加登録が必要なコンテストに未登録のまま提出したときの動作は、まだ確認していません。Rust の選択肢が複数ある場合の動作も、まだ確認していません（「Rust」で始まる最初のものを選びます）。C++ の Clang 版や IOI-Style、Python の Codon では提出しません。
- **AtCoder Problems**：非公式のサービスなので、データの形が変わったり、使えなくなったりすることがあります。そのときは理由を表示し、ほかの機能はそのまま使えます。
- **残り時間**：コンテストの時間の延長は、残り時間が 0 になったときに読み直して反映します（それより前に延長されても、0 になるまでは元の終了時刻で数えます）。AtCoder のサーバーの時刻と Mac の時計のずれは考えません。
- **出力の末尾の改行**：サンプルテストの `whitespace`（空白の違いを無視）は、AtCoder 公式の説明の文言どおり、期待出力が改行で終わるなら、出力も空白で終わることを求めます（`print!` で改行を出さないと AC になりません）。実際のジャッジがどう判定するかは確認していません。
- **安全性**：信頼したフォルダのコードは、制限なし（サンドボックスなし）で実行されます。デバッグ中は、デバッグコンソールから LLDB のコマンドを使えます。ログインのセッションはキーチェーンに保存しますが、同じユーザーのほかのプログラムから読める場合があります。
- **Windows**：対応していません。
